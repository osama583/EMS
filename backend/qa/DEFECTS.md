# AI assistant — defect registry

Adversarial QA of `POST /api/v1/ai/ask`, run against the live Supabase database with real seeded
accounts across 12 roles. Every data claim was graded against ground truth queried directly from
PostgreSQL, so a confidently-wrong answer is detectable rather than merely plausible.

Harness: `qa/harness.py` (logs in as real accounts, sends the same `history` array the Angular
client sends). Fixes: `qa/apply_fixes.py` re-applies the core set idempotently; `qa/ai-fixes.patch`
is a full snapshot.

## Open, not fixed by design

| Finding | Why it is left |
|---------|----------------|
| Ties reported as a unique maximum (R2-15, RG5-a: three clubs share 2 members, one is named "the biggest") | Cosmetic-to-medium. Needs the query to return all tied rows; a prompt rule alone would have the model assert a tie it cannot see. |
| "which events are free?" answered "I don't have that information" (R4-38) | `cost_amount` is exposed, but it is NULL for 10 of 11 events. NULL means *unspecified*, not provably *free* — making the model assert "free" from a null would trade an under-answer for a wrong one. This is a data-modelling gap, not a prompt bug. |
| `_ROLE_CAPABILITIES` claims Cafeteria Admin can "view operational reports" on a `reports` page the role has no grant for (`test_role_capabilities.py`, pre-existing failure) | Stale capability data in `knowledge_base.py`, unrelated to this QA pass. `role_has_page_grant()` filters the unreachable line out at runtime, so the assistant does not repeat the false claim — but the source data should still be corrected. |
| `GET /auth/dev-users` advertises `Demo-EMS-2026` for external users, but those accounts reject it | Self-registered external accounts keep their own password. The demo picker's promise is wrong for that role, which blocked one planned test. |
